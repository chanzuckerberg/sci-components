Icons

The icons of the Science Design System: the Phosphor set, and the handful SDS draws itself.

A separate package: the icons SDS draws itself ship as @czi-sds/icons, not as part of @czi-sds/components. They are built on Phosphor's own IconBase, so @phosphor-icons/react is required at runtime, and an app installs both. Neither depends on @czi-sds/components, so icons can be used without the rest of the design system.

Phosphor covers around 1,500 icons in six weights. @czi-sds/icons adds a few of its own, either where Phosphor has no equivalent or where SDS wants its own version of one it does have; the Custom Icons page lists them. Both are the same kind of component, taking the same props and reading the same IconContext, so the only difference is where you import from.

Why Phosphor is a peer dependency: it keeps one copy of Phosphor in your app. That single copy is what lets one IconContext style the icons from both packages, so a provider you render reaches an SDS icon and a Phosphor icon alike. A bundled copy would be a second context that your provider never reaches.

Requiring this package from CommonJS does not work: @phosphor-icons/react declares itself as an ES module and ships its CommonJS build as a .js file, so Node reads that build as ESM and it exports nothing. Anything depending on it through require gets an empty IconBase. Bundlers are unaffected, since they resolve the ESM build, and so is import. It only bites a raw require at runtime, such as a Jest setup still running in CommonJS, where the fix is to let Jest resolve the ESM build.

Usage

Import the icon you want from the package it belongs to. Browse the Phosphor set at phosphoricons.com, where the name shown plus an Icon suffix is the export name.

Unlike the rest of the design system, icons need no theme provider: they take their size and color from props, and default to the surrounding text color.

Default Icon

An icon needs no props at all: it renders at 1em in the current text color.

Icon Sizes

size sets both width and height, and takes a number or a string with units. SDS icon sizes are 12, 16, 24 and 32 pixels; they are values you pass rather than a set the component enforces, so they are also available as the --sds-icon-size-* CSS variables and through the getIconSizes theme selector in @czi-sds/components.

Icon Colors

color takes any CSS color string. It defaults to currentColor, so an icon with no color of its own follows the text color around it, which is usually what you want inside a button or a link.

Shared defaults

IconContext applies props to every icon beneath it, so an app can set its icon size and color once. It comes from Phosphor and covers both packages. Props on an individual icon win over the context, and you can nest providers to style separate regions differently.

Weights

Phosphor's icons carry six drawings and pick between them on weight. Each SDS icon ships a single drawing, so it accepts weight for API parity and looks the same at every value. The top row below is a Phosphor icon, the bottom row an SDS one.

Props

Icons accept every prop an svg element does, including className, style, onClick and aria-*. These are the ones specific to icons.

Accessibility

An icon beside a text label is decorative: leave alt off and add aria-hidden so a screen reader does not announce it twice. An icon standing on its own carries meaning, so give it an alt, or label the control that contains it with aria-label.

Composability

Icons render their children below the icon's own paths, so you can slot in background shapes, filters, or SMIL animations. Slotted elements are positioned in the icon's 256x256 coordinate space, which holds for the SDS icons too.

Build performance

Contributing

The package source lives in packages/icons of the SDS repository, and the contribution guidelines apply here as they do to the main package. An icon is added to SDS only where Phosphor has no equivalent or where the design team wants its own version, so agree a new one before building it: post in the #sci-design-system-support channel in Slack. The Custom Icons page has the mechanics once it is agreed.
