Icons

Icons are generally used in conjunction with text to further clarify the outcome of a user's action. Occasionally they are used as buttons themselves without accompanying text.

SDS draws on Phosphor Icons for its icon set, and adds the handful of icons Phosphor has no equivalent for in @czi-sds/icons. This page covers when and how to use an icon; the Icons documentation covers the code.

Engineers: the Icon component is deprecated. Import icons from @phosphor-icons/react, or from @czi-sds/icons for the ones SDS draws itself. See Migrating from Icon .

Choosing an icon

Search the Phosphor set first, at phosphoricons.com. It is large, consistently drawn, and maintained upstream, so an icon taken from it will sit correctly beside every other icon in the interface.

SDS keeps a small set of its own, for one of two reasons: either Phosphor has no equivalent, which covers the brand marks and the concepts specific to the science these products do, or Phosphor has something close and we have decided we want our own version of it, which covers the generative and predictive affordances and a few data-visualisation and panel controls. The Custom Icons page lists them and says which is which.

Where an icon appears on that page it takes precedence over a Phosphor lookalike, even where the two are similar. If a concept is missing from both, raise it with the design team rather than settling for the nearest approximation, since an icon that reads wrongly is worse than a text label.

There is a fifth size below these, 10px, exposed as --sds-icon-size-xxs-height and --sds-icon-size-xxs-width. It is small enough to be hard to read and is best avoided in new work. Every variable above is also published as an SCSS variable, for example $sds-icon-size-l-height, and is available from the theme through the getIconSizes selector.

Weights

Phosphor draws each of its icons at six weights, from thin to bold, plus fill and duotone. Pick one weight and hold to it across a product; regular is the default and suits nearly everything. The exception is a state change, where two weights of the same icon read well as a pair, such as a regular star for an empty rating and a fill star for a set one.

The icons SDS draws itself are drawn once and look the same at every weight, so do not build a design around weight changes on those.

Color

An icon takes any color, and by default it inherits the text color next to it, which is usually right: an icon inside a button or a link should move with the text it belongs to. Where an icon carries meaning of its own, such as an intent or a status, take the color from the semantic palette rather than picking a hue.

Accessibility

An icon beside a text label is decorative and should be hidden from screen readers, so the label is announced once rather than twice. An icon standing on its own carries meaning and needs an accessible name, either on the icon or on the control containing it. Do not rely on an icon alone to convey something critical: pair it with text, or with a tooltip at minimum.
